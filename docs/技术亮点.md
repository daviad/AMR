# 技术亮点

## 一、端到端闭环

**1. 五条链路在同一个工程里闭环，不是零散 demo。**
地图与定位、导航与任务、视频、监控大屏、告警都接在同一套启动脚本和同一份话题契约上；一条命令拉起仿真端，App 连上就能点图导航。
依据：[amr_start.sh](../amr_start.sh)、[full_bringup.launch.py](../amr_sim_ws/src/amr_bringup/launch/full_bringup.launch.py)

**2. 指令不是「发出去就算」，有完整生命周期。**
`cmd_id` 幂等（重复指令只回放上次 ACK/Result，不重复执行）、`ttl_ms` 过期拒收（避免迟到的物理动作）、ACK/Feedback/Result 三段超时、端到端 trace。MQTT 只保证「到达下一跳」，业务语义由桥接节点补。
依据：[command.dart](../amr_app/packages/amr_contracts/lib/src/command.dart#L183-L201)（TTL 8000 / ACK 1200 / Feedback 3000 ms）、[mission_bridge.py](../amr_sim_ws/src/amr_comm/scripts/mission_bridge.py#L134-L153)

**3. 契约包做单一事实源。**
话题名、消息模型、指令状态机抽成纯 Dart 包 `amr_contracts`，App 与仿真端共用一份定义，避免两端各写一套字符串。
依据：[amr_contracts](../amr_app/packages/amr_contracts/lib/src/topic_mapping.dart)

---

## 二、通信分层

**4. 三类流量走三条通道，各用各的强项。**
遥测是高频小包 → WebSocket（rosbridge）；指令要可靠、要能离线重连 → MQTT；视频要低延迟 → WebRTC。用一条通道全塞会互相拖累。
依据：[topic_mapping.dart](../amr_app/packages/amr_contracts/lib/src/topic_mapping.dart)、[constants.dart](../amr_app/lib/core/constants.dart#L15-L30)

| 流量 | 通道 | 端口 | 关键话题 |
|---|---|---|---|
| 遥测 | rosbridge WebSocket | 9090 | `/map` `/scan` `/tf` `/odom` `/plan` `/amcl_pose` |
| 指令 | MQTT TCP（浏览器用 WS） | 1884 / 9002 | `amr/cmd/goal`、`cancel`、`inspection/*`、`mode`、`estop`、`return_charge` |
| 视频 | WHEP / ICE | 8889 / 8189(UDP) | `camera`、`camera_low` |

**5. QoS 按语义分级，不是一刀切。**
指令入站 QoS 1（至少一次，配合 `cmd_id` 去重）；状态上报 QoS 0（允许丢，丢了下一条补上）；ACK/Result QoS 1，Feedback/Trace QoS 0。App 侧开 `autoReconnect` + `resubscribeOnAutoReconnect` + 遗嘱 `amr/status/app_offline`。
依据：[mqtt_client.yaml](../amr_sim_ws/src/amr_comm/config/mqtt_client.yaml#L24-L105)、[mqtt_client.dart](../amr_app/lib/comm/mqtt_client.dart#L46-L51)

## 三、弱网、超时、重连、自适应

**6. 视频断流用指数退避重连，避免把服务打垮。**
重连间隔 `min(10, 1 << min(attempt, 3))` → 1/2/4/8/10 s 封顶；配合连接健康度状态机 CONNECTING / HEALTHY / DEGRADED / LOST。
依据：[video_stream_service.dart](../amr_app/lib/services/video_stream_service.dart#L28-L66)、[:561](../amr_app/lib/services/video_stream_service.dart#L561)

**7. 码流自适应是「主/低两路切换」，不是连续 ABR。**
连续 DEGRADED ≥2 次切低码流，连续 HEALTHY ≥4 次回主码流，切换后 10 s 冷却防抖。开销小、行为可预测，适合两路固定档位。
依据：[video_stream_service.dart](../amr_app/lib/services/video_stream_service.dart#L634-L637)、[:758-780](../amr_app/lib/services/video_stream_service.dart#L758-L780)

**8. rosbridge 用心跳判活，而不是等 TCP 报错。**
2 s 重连定时器 + 5 s ping，超过 10 s 无响应主动重连——半开连接不会一直挂在那里假装在线。
依据：[rosbridge_client.dart](../amr_app/lib/comm/rosbridge_client.dart#L104-L113)

**9. 源切换是手动兜底，不是自动降级。**
WebRTC 不通时需在相机页手动切 RTSP(TCP) 或 rosbridge JPEG。这是当前实现的真实边界。
依据：[constants.dart](../amr_app/lib/core/constants.dart#L24-L41) 注释、[camera_page.dart](../amr_app/lib/pages/camera_page.dart)

## 四、视频链路

**10. 一次采集，两路编码，按需拉取。**
Gazebo 相机原始帧 → GStreamer 同时编出主码流（320×240 / 700 kbps）与低码流（160×120 / 220 kbps），经 `rtspclientsink protocols=tcp` 推到 MediaMTX 的 `camera` / `camera_low`。
依据：[gst_video_source.py](../amr_sim_ws/src/amr_gazebo/scripts/gst_video_source.py#L75-L96)、[:157-L176](../amr_sim_ws/src/amr_gazebo/scripts/gst_video_source.py#L157-L176)

> 编码器是 **`x264enc`（软件编码）**，不是硬件编码；硬件解码发生在 App 侧。

**11. 主链路是 WHEP，不是裸 RTP。**
App 默认走 `POST /camera/whep` 做 SDP 交换，媒体走 ICE（UDP 8189）；MediaMTX 用 `webrtcIPsFromInterfaces` 自动枚举本机地址，另加 `10.0.2.2`（模拟器 NAT）与 `127.0.0.1` 覆盖本地映射。
依据：[mediamtx.yml](../amr_sim_ws/src/amr_gazebo/config/mediamtx.yml#L23-L37)、[constants.dart](../amr_app/lib/core/constants.dart#L24-L30)

**12. 内网穿透只做到 ICE host candidate 这一层。**
`mediamtx.yml` 没有配置 `webrtcICEServers`，即**没有 STUN/TURN**。当前能通是因为机器人在同一内网/模拟器 NAT 内；跨公网需要另加 STUN/TURN，属于未实现项。
依据：[mediamtx.yml](../amr_sim_ws/src/amr_gazebo/config/mediamtx.yml#L28-L37)（无 ICE server 配置）

**13. 用 `fvp` 替换 `video_player` 的底层实现，让同一套播放代码支持 RTSP 且硬解。**
`fvp`（MDK 后端）在非 Web 端注册，`video_player` API 不变；RTSP 强制 `tcp` interleaved（因为 `adb reverse` 只转 TCP），`lowLatency: 2` 适配直播。硬解由 fvp/MDK 负责；另一条 rosbridge JPEG 兜底链路才是软解。
依据：[main.dart](../amr_app/lib/main.dart#L17-L27)、[pubspec.yaml](../amr_app/pubspec.yaml#L20)

**14. Web 端不复用 WebRTC，直接走 HLS。**
浏览器端的编解码、端口、自动播放策略差异太大，HLS + `hls.js` 更稳；代价是延迟高，但大屏场景可接受。
依据：[mediamtx.yml](../amr_sim_ws/src/amr_gazebo/config/mediamtx.yml#L11-L21)、[WEB大屏操作手册.md](WEB大屏操作手册.md)

## 五、UI 与地图

**15. 栅格地图自绘，不依赖地图控件。**
`CustomPainter` + `MapLayer` 抽象（底图 / 路径 / 机器人 / 巡检点 / 目标点），视口变换统一为 `screen = pixel * scale + offset`，手势缩放围绕焦点。好处是图层可插拔、刷新只重绘脏层。
依据：[lib/map/](../amr_app/lib/map/)、[map_painter.dart](../amr_app/lib/map/map_painter.dart)、[map_viewport.dart](../amr_app/lib/map/map_viewport.dart)

**16. 大屏与 App 共用同一路由，不是两套前端。**
`/dashboard` 是共用页面，Web 只是多一个 `flutter build web` 产物；布局地图 60% + 视频/状态/控制 40%，顶栏显示 MQTT/ROS 连接状态。
依据：[dashboard_page.dart](../amr_app/lib/pages/dashboard_page.dart)、[amr_web_start.ps1](../amr_web_start.ps1#L226)

## 六、ROS 2 与仿真

**17. 环境与机器人用 SDF + URDF/Xacro 描述，Gazebo 里真跑物理。**
场景是 SDF 1.9（围墙、房间分隔、障碍物、充电桩标记区）；机器人用 Xacro 拆成 base / camera / imu / lidar 四个子模块再组合，改传感器只动一个文件。
依据：[indoor.world](../amr_sim_ws/src/amr_gazebo/worlds/indoor.world#L2)、[urdf/](../amr_sim_ws/src/amr_description/urdf/)

**18. 建图、定位、导航各用专用栈，不自己造轮子。**
Cartographer 2D（激光 + IMU + 轮式里程计先验）建图；AMCL 在已知地图定位；Nav2 用 `NavfnPlanner` 全局规划 + `DWBLocalPlanner` 局部控制，配 `velocity_smoother`、`collision_monitor`、`behavior_server`、`docking_server`。
依据：[cartographer_2d.lua](../amr_sim_ws/src/amr_slam/config/cartographer_2d.lua)、[nav2_params.yaml](../amr_sim_ws/src/amr_nav/config/nav2_params.yaml)

**19. 多个 bridge 各管一段边界，消息转换不散落在业务里。**
- `ros_gz_bridge`：ROS ↔ Gazebo（`/cmd_vel`、`/scan`、`/imu/data`、`/odom`、`/tf`、`/joint_states`、`/camera/image_raw`、`/clock`）
- `image_transport republish`：raw → compressed（ros_gz_bridge 无 Image→Compressed 模板特化）
- `mission_bridge`：MQTT ↔ Nav2 Action
- `mqtt_client`：ROS ↔ MQTT 状态/指令
- `inspection_node`：模式、巡检、回充、告警
依据：[bridge_topics.yaml](../amr_sim_ws/src/amr_gazebo/config/bridge_topics.yaml)、[full_bringup.launch.py](../amr_sim_ws/src/amr_bringup/launch/full_bringup.launch.py#L119-L126)、[mission_bridge.py](../amr_sim_ws/src/amr_comm/scripts/mission_bridge.py)

**20. 建图穿墙,是定位到了两个具体来源。**
一是差速驱动插件锁存最后一条非零速度指令，停车后轮子还在转 → 加 `cmd_vel_watchdog`，0.5 s 无指令归零；二是前脚轮摩擦让原地旋转只转 ~40% → 把 `front_caster_link` 的 `mu1/mu2` 置 0。修完后里程计/真值偏航比 >0.95，才敢重新把 `use_odometry` 打开。
依据：[cartographer_2d.lua](../amr_sim_ws/src/amr_slam/config/cartographer_2d.lua#L15-L20)、[slam_no_wall_pass_and_contact_params.md](../amr_sim_ws/doc/slam_no_wall_pass_and_contact_params.md)

**21. 对「长直墙几何退化」做了 A/B，而不是拍脑袋。**
关掉 odom 时 scan matching 在长墙方向退化，实测 x 向漂移 34 m；`POSE_GRAPH.optimize_every_n_nodes` 20 比 35 更差（位姿误差 0.128→0.784 m），已回滚。
依据：[cartographer_2d.lua](../amr_sim_ws/src/amr_slam/config/cartographer_2d.lua#L19)、[:51](../amr_sim_ws/src/amr_slam/config/cartographer_2d.lua#L51)

## 七、术语勘误（原始描述 → 实际技术名）

| 原始写法 | 实际名称 | 说明 |
|---|---|---|
| `Sdl rfdl xatr` | **SDF / URDF / Xacro** | SDF 描述世界，URDF 描述机器人，Xacro 是 URDF 的宏预处理 |
| `Categrapher` | **Cartographer** | Google 的 2D/3D SLAM 库 |
| `acm 定位` | **AMCL** | Adaptive Monte Carlo Localization，粒子滤波定位 |
| `stun strun ice dsp` | **STUN / TURN / ICE / SDP** | 其中 SDP 是会话描述（信令），不是 `dsp`；但**本仓库未配 STUN/TURN** |
| `fpv 插件` | **`fvp`** | `pubspec.yaml` 实际依赖名，MDK 后端，不是 FPV 图传 |
| `rtp 降级` | **RTSP**（手动兜底） | MediaMTX 开了 RTSP 18554，App 相机页手动切；不是 RTP 自动降级 |
| `gstreamer 硬编码` | **GStreamer 软件编码** | 实际是 `x264enc`，硬件解码在 App 侧 |

## 八、条件限制未实际实现的功能

- **GPU 零拷贝 / 无序列化 / 无上下文切换**：仓库里没有对应的零拷贝或共享内存实现证据，属于平台/库的潜在特性
- **STUN/TURN 穿透**：未配置，仅 ICE host candidate；跨公网不通。
- **自动降级到 RTSP**：未实现，是相机页手动切换。
- **硬解失败自动回退软解**：仓库未配置该逻辑；硬解由 fvp/MDK 承担，软解只出现在 rosbridge JPEG 兜底链路。
- **连续自适应码率（ABR）**：未实现，只有主/低两档 + 防抖切换。
- **硬件编码**：未使用，`gst_video_source.py` 是 `x264enc`。
- **真机 / iOS 验证**：仅 Android 模拟器与 Web 实测；iOS 未 `pod install`、未编译、未运行；真机未实测。
