# AMR 业务网关收口（feature/gateway）

> 状态：设计定稿，本分支实现
> 适用范围：Flutter App（Android / iOS / Web）、仿真端（ROS 2 Jazzy + Gazebo + Nav2）、MQTT Broker、MediaMTX
> 一句话结论：**把"谁能控制车、指令走到哪一步、地图给谁"从 App 内存搬到机器人侧的一个 Python 网关进程**，App 只保留 HTTP（业务）、WebSocket（推送）、WebRTC/HLS（视频）三条出口。

---

## 1. 现状与问题

### 1.1 现状拓扑

```
Flutter App ──ws://<host>:9090 ──> rosbridge ──> ROS 2（/map /scan /tf /amcl_pose /plan）
Flutter App ──mqtt://<host>:1884 ─> mosquitto ──> mqtt_client(ROS) ──> /amr/cmd/* ──> mission_bridge ──DDS──> Nav2
Flutter App ──WebRTC/HLS ───────> MediaMTX
```

- 业务指令与遥测各自直连，App 承担了 `cmd_id` 生成、超时判定、重试、状态机、trace 记录。
- `mosquitto.conf` 两个 listener 都监听 `0.0.0.0` 且 `allow_anonymous true`。
- 机器人侧 `mission_bridge.py` 已有：`cmd_id` 幂等（`_seen` 256 条）、`ttl_ms=8000` 过期判定、ACK/FEEDBACK/RESULT 回执。
- 视频链路（MediaMTX：RTSP 18554 / WHEP 8889 / HLS 18888）与业务无关，保持现状。

### 1.2 两个必须先解决的具体风险

**风险 A：App 直连 rosbridge 导致 QoS 首注册锁定**

`/map` 由 `map_server` 以 `RELIABLE + TRANSIENT_LOCAL`（latched）发布，且只在加载地图时发一帧。rosbridge 对**一个 topic 只建立一个 DDS 订阅**，该订阅的 QoS 由**第一个 `subscribe` 请求**决定，后续客户端只能复用，无法再改。只要有一个客户端（旧版 App、临时脚本、Web 大屏）先以默认 `VOLATILE` 订阅 `/map`，后到的客户端就永久拿不到那唯一一帧，UI 停在"等待地图数据…"。这个 bug 与客户端代码质量无关，是"多客户端共享一条 rosbridge 连接"的结构性问题。

**风险 B：匿名可写控制通道**

`allow_anonymous true` + `0.0.0.0` 监听意味着**同一网段任何进程**都能 `mosquitto_pub -t amr/cmd/goal` 直接驱动实车，没有身份、没有锁、没有审计。把控制面放在 App 里，等于把"谁按下了按钮"交给一个可以被任意客户端冒充的通道。

### 1.3 其余由直连派生的问题

| 问题 | 现象 | 根因 |
|---|---|---|
| 重试必然失败 | `retry()` 复用旧 `timestamp_ms`，超过 `ttl_ms=8000` 被 `mission_bridge` 判 `EXPIRED` | 过期判定在机器人侧，重发逻辑在 App 侧，时间戳没有刷新 |
| 任务状态不可恢复 | 换设备、刷新 Web 页、App 进程被杀，任务状态全部丢失 | 状态机只存在 App 内存 |
| 多端抢控 | App 与 Web 大屏可同时下发，最后写入者赢 | 没有 `device_lock` 概念 |
| 无法审计 | 谁在什么时候发过什么指令，只存在于客户端日志 | 机器人侧没有持久化 |
| 协议耦合 | App 要同时理解 rosbridge op 码 + MQTT topic + ROS 消息结构 | 三个协议栈都暴露给客户端 |

## 2. 目标架构

### 2.1 拓扑

```
                    ┌──────────────────────────────┐
Flutter App ──HTTP──▶│  Python 网关 (amr_gateway)   │
   (Android/iOS/Web) │  ├ HTTP  8080  业务/地图/快照 │
        │            │  ├ WS    8081  位姿/路径/扫描 │
        │            │  │             任务/状态/告警  │
        │            │  ├ SQLite 任务/审计/device_lock│
        │            │  └ rosbridge 客户端（唯一）     │
        │            └───────┬───────────────┬────────┘
        │                    │MQTT(内网+ACL)  │ws://127.0.0.1:9090
        │                    ▼               ▼
        │              mosquitto 1884    rosbridge ──DDS──▶ /map /scan /tf /amcl_pose /plan
        │                    │
        │                    ▼
        │              mqtt_client(ROS) ──/amr/cmd/*──▶ mission_bridge ──DDS──▶ Nav2
        │
        └──WebRTC/HLS──▶ MediaMTX（视频，不经网关，保持现状）
```

关键约束：

1. **网关是唯一 MQTT 发布者**（`amr/cmd/#`）和**唯一 rosbridge 客户端**。App 不连 MQTT、不连 rosbridge。
2. 网关是**纯 Python 单进程**，与 `mission_bridge` 同语言，复用其 JSON 消息模型，不引入第二个运行时。
3. 网关**不实现 ROS 节点**：它通过 rosbridge 拿话题，因此不需要 `rclpy`、不受 DDS 域/中间件配置影响，可独立于仿真进程重启。
4. 视频链路不经过网关：WebRTC/HLS 走 MediaMTX 的 8889/18888，网关不转发媒体流，避免单进程成为视频带宽瓶颈。

### 2.2 为什么这样分层（面试讲稿主线）

- **控制面与数据面分开**：HTTP 适合"一问一答 + 幂等 + 可重放"的业务动作（下发/取消/查询/地图下载），WS 适合"服务器主动、低频、可丢"的遥测推送。二者都不需要客户端理解 ROS。
- **状态归属机器人侧**：任务状态、幂等、超时、审计必须活在"离执行器最近"的地方。App 只是视图，换端、刷新、断线都不影响任务。
- **单写者原则**：控制通道只有一个写入者（网关），MQTT ACL 从机制上保证这一点；App 越权发布在 broker 层被拒绝，而不是靠客户端自觉。
- **rosbridge 降级为调试工具**：rosbridge 本来是"浏览器看 ROS"的调试桥，不适合作为生产控制面；网关独占它可以固定 QoS，也避免 QoS 首注册锁定。
- **保留 MediaMTX**：媒体流有自己的传输特性（ICE/码率/抖动缓冲），塞进业务网关只会让网关变成瓶颈，且 WebRTC 已在三端验证通过。

## 3. 协议与组件选型

| 层 | 选型 | 理由 | 放弃的替代 |
|---|---|---|---|
| 业务 API | HTTP/1.1 + JSON（`http.server` 标准库） | 无状态、可缓存、可用 curl 复现；标准库零依赖 | gRPC（见 §13） |
| 推送 | WebSocket + JSON（`websockets` 库） | 双向、低延迟、三端统一（Web 原生、移动端 `web_socket_channel`） | SSE（单向、Web 端够用但移动端/自动重连弱）、轮询（延迟与流量差） |
| 指令下行 | MQTT over TCP（`paho-mqtt`） | 机器人侧已有 `mqtt_client` ROS 桥和 `mission_bridge`，改动最小；QoS1 + 业务层幂等 | 直连 ROS、HTTP 转 ROS |
| ROS 读取 | rosbridge（`websockets` 客户端） | 不引入 `rclpy`，网关不需要 source ROS 环境；独占订阅可固定 `/map` 的 latched QoS | rclpy 节点（与 `amr_comm` 进程耦合、DDS 配置敏感） |
| 持久化 | SQLite（`sqlite3` 标准库） | 单机单进程、任务量小、事务足够；零额外进程 | Postgres（重）、Redis（多一个进程） |
| 地图 | PGM(P5) + JSON 元信息，落盘 | ROS 生态原生格式、可用任意图片工具查看；App 端可还原 OccupancyGrid | 直接透传 OccupancyGrid JSON（体积大、无版本语义） |
| 视频 | MediaMTX（不变） | 已验证，独立进程 | 网关转发（带宽/复杂度） |

**新增 Python 依赖**（写进 `requirements.txt`，均只做一件事）：

- `paho-mqtt`：Python 侧 MQTT 客户端，标准库没有。
- `websockets`：同时提供 WS 服务端与 rosbridge 客户端，避免再引入 `websocket-client` / `aiohttp`。

`http.server`、`sqlite3`、`json`、`asyncio` 均为标准库，不新增。

## 4. 完整数据流

### 4.1 下行指令（导航）

```
App POST /api/v1/tasks {type:navigate,x,y,theta,holder}
  → 网关校验 token / device_lock / 是否已有活动任务
  → 生成 cmd_id、trace_id，写 tasks 表（phase=CREATED）
  → 发布 MQTT amr/cmd/goal
      {cmd_id, trace_id, timestamp_ms=now, ttl_ms=8000, payload:{x,y,theta}}
  → phase=PUBLISHED，审计一行，WS 广播 task
  → mission_bridge 收 → ACK/FEEDBACK/RESULT 发 amr/cmd/ack|feedback|result
  → 网关订阅回执 → 按 cmd_id 关联 → 更新 tasks 表 + 审计 + WS 广播
```

网关发布前自检 `timestamp_ms` 是"现在"（不是 App 传来的旧值），这是修复 §1.3 重试缺陷的根因位置。

### 4.2 上行回执

- `amr/cmd/ack`：`ACCEPTED` → `ACCEPTED`；`REJECTED` + `error_code` → 任务终态 `FAILED`。
- `amr/cmd/feedback`：`nav_state / number_of_recoveries / distance_remaining / eta_sec` → `EXECUTING`，`heartbeat=true` 只刷新 `updated_at`。
- `amr/cmd/result`：`SUCCEEDED` / `CANCELLED` / `FAILED` → 终态，写 `result_json`。
- 同一 `cmd_id` 的重复回执只更新、不重复广播终态；未知 `cmd_id` 的回执记 `audit` 但不建任务（防止串台）。

### 4.3 地图

```
rosbridge /map（TRANSIENT_LOCAL, keep_last 1）
  → 网关解码 OccupancyGrid
  → 写 ~/.amr_gateway/maps/map.pgm（P5，行序上→下，0=占用 254=空闲 205=未知）
  → 写 ~/.amr_gateway/maps/map.json（version = sha1(width|height|resolution|origin|data)[:12]）
  → WS 广播 {"type":"map_meta","version":...}
App GET /api/v1/map/meta → 版本相同用本地缓存；不同 GET /api/v1/map/pgm?version=...
```

网关每次收到 `/map`（重新建图/换图）都会生成新 version，App 按 version 判断是否重新下载。

### 4.4 视频

不经过网关：App 仍按 `whepUrl()` / `rtspUrl()` / HLS 地址直连 MediaMTX，网关不参与鉴权也不转发。唯一变化是 App 的拍照功能改走网关 `GET /api/v1/snapshot`（网关缓存最近一帧 `CompressedImage`），从而 App 不再需要 rosbridge。

## 5. HTTP API 契约

Base：`http://<host>:8080`；除 `/healthz` 与 `/api/v1/auth/login` 外均要求
`Authorization: Bearer <token>`（默认 `amr-dev-token`，来自 `gateway.json`）。
请求/响应均为 `application/json`，错误统一为：

```json
{"error": {"code": "LOCKED", "message": "device is controlled by web-dashboard"}}
```

### 5.1 端点总表

| Method | Path | 说明 |
|---|---|---|
| GET | `/healthz` | 存活/依赖状态，不需要 token |
| POST | `/api/v1/auth/login` | 换取 token（内网静态令牌） |
| GET | `/api/v1/map/meta` | 地图元信息与版本 |
| GET | `/api/v1/map/pgm?version=` | 下载 PGM |
| POST | `/api/v1/tasks` | 下发导航任务 |
| GET | `/api/v1/tasks?limit=&phase=` | 任务列表 |
| GET | `/api/v1/tasks/{cmd_id}` | 单任务详情 |
| POST | `/api/v1/tasks/{cmd_id}/cancel` | 取消 |
| POST | `/api/v1/tasks/{cmd_id}/retry` | 重试（网关重打时间戳） |
| POST | `/api/v1/commands` | 非任务类指令（模式/急停/回充/巡检） |
| GET | `/api/v1/lock` | 查询控制锁 |
| POST | `/api/v1/lock` | 获取/续租控制锁 |
| DELETE | `/api/v1/lock?holder=` | 释放控制锁 |
| GET | `/api/v1/snapshot` | 最新 JPEG 快照（替代 App 的 rosbridge 拍照） |

### 5.2 关键字段

`GET /healthz` → `200`

```json
{"ok": true, "uptime_s": 12.3, "mqtt": true, "rosbridge": true,
 "map_version": "9f2c1a7b3d05", "active_task": null}
```

`POST /api/v1/auth/login` body `{"device_id":"app-pixel"}` → `200`

```json
{"token": "amr-dev-token", "expires_at": null}
```

`GET /api/v1/map/meta` → `200`（未收到地图时 `map_version=null`，HTTP 404 `MAP_NOT_READY`）

```json
{"version": "9f2c1a7b3d05", "width": 400, "height": 320,
 "resolution": 0.05, "origin": {"x": -10.0, "y": -8.0, "yaw": 0.0},
 "row_order": "top_down", "encoding": "P5",
 "pgm_url": "/api/v1/map/pgm?version=9f2c1a7b3d05",
 "updated_at": 1794136000000}
```

`GET /api/v1/map/pgm`：`Content-Type: image/x-portable-graymap`，P5 文件头 + 像素。
`version` 不匹配当前版本 → `409 MAP_VERSION_MISMATCH`（客户端重新取 meta）。

`POST /api/v1/tasks` body：

```json
{"type": "navigate", "x": 1.5, "y": -0.4, "theta": 0.0,
 "ttl_ms": 8000, "holder": "app-pixel"}
```

→ `202`

```json
{"cmd_id": "cmd-0f31...", "trace_id": "trace-0f31...", "phase": "PUBLISHED",
 "created_at": 1794136000123}
```

任务对象（列表/详情/WS 共用）：

```json
{"cmd_id": "...", "trace_id": "...", "type": "navigate",
 "payload": {"x": 1.5, "y": -0.4, "theta": 0.0},
 "phase": "EXECUTING", "created_at": 1794136000123,
 "updated_at": 1794136001999, "error_code": null, "error_msg": null,
 "result": {"status": "SUCCEEDED", "error_code": null, "latency_ms": 3412.5}}
```

`POST /api/v1/tasks/{cmd_id}/cancel` body `{"holder":"app-pixel"}` → `202`

```json
{"cmd_id": "cancel-...", "target_cmd_id": "...", "phase": "CANCEL_REQUESTED"}
```

`POST /api/v1/tasks/{cmd_id}/retry` body `{"holder":"app-pixel"}` → `202`
（同一 `cmd_id`，`timestamp_ms` 重新生成；`ttl_ms` 从任务创建时的值取）

`POST /api/v1/commands` body：

```json
{"name": "mode|estop|return_charge|inspection_start|inspection_stop",
 "payload": {"mode": "auto"}, "holder": "app-pixel"}
```

→ `202` `{"topic":"amr/cmd/mode","published":true}`

`GET /api/v1/lock` → `200` `{"holder":"app-pixel","expires_at":1794136060000}` 或 `{"holder":null}`

`POST /api/v1/lock` body `{"holder":"app-pixel","ttl_s":60}` → `200` 同上；被他人占用 → `409 LOCKED`

`GET /api/v1/snapshot` → `200 image/jpeg`；无帧 → `503 NO_FRAME`

### 5.3 错误码

| HTTP | code | 触发 |
|---|---|---|
| 400 | `INVALID_ARGUMENT` | JSON 解析失败、缺字段、类型错误 |
| 401 | `UNAUTHORIZED` | token 缺失/错误 |
| 404 | `NOT_FOUND` / `MAP_NOT_READY` | 任务不存在 / 地图未收到 |
| 409 | `LOCKED` | 控制锁被其他 holder 持有 |
| 409 | `TASK_ACTIVE` | 已有非终态任务（导航单任务串行） |
| 409 | `MAP_VERSION_MISMATCH` | PGM 版本已过期 |
| 422 | `BAD_PAYLOAD` | 坐标缺失/非数值 |
| 503 | `MQTT_UNAVAILABLE` | MQTT 未连接，指令未发布 |
| 503 | `NO_FRAME` | 还没有压缩图像帧 |

## 6. WebSocket 消息契约

地址：`ws://<host>:8081/ws?token=amr-dev-token`（浏览器无法设置请求头，token 放 query）。

客户端 → 服务端：

```json
{"op": "subscribe", "topics": ["pose","plan","scan","task","battery","mode","inspection","alert","lock","map_meta"]}
{"op": "ping"}
```

服务端 → 客户端（`type` 为判别字段，未订阅该类则不发送）：

```json
{"type":"hello","gateway":"0.1.0","ts":1794136000000,"topics":["pose","plan","task"]}
{"type":"pose","x":1.02,"y":-0.33,"theta":0.12,"source":"amcl","stamp_ms":1794136000100}
{"type":"plan","points":[[0.0,0.0],[0.5,0.2]],"stamp_ms":1794136000150}
{"type":"scan","points":[[1.2,0.4]],"stamp_ms":1794136000200}
{"type":"task","cmd_id":"...","phase":"EXECUTING","event":"feedback",
 "data":{"nav_state":"CONTROLLING","distance_remaining":2.31,"eta_sec":18.0}}
{"type":"task","cmd_id":"...","phase":"SUCCEEDED","event":"result",
 "data":{"status":"SUCCEEDED","latency_ms":3412.5}}
{"type":"battery","data":{"level":85,"voltage":12.1,"charging":false}}
{"type":"mode","data":{"mode":"auto"}}
{"type":"inspection","data":{"state":"running","progress":2,"total":5}}
{"type":"alert","data":{"level":"warn","code":"LOW_BATTERY","message":"..."}}
{"type":"lock","holder":"app-pixel","expires_at":1794136060000}
{"type":"map_meta","version":"9f2c1a7b3d05","width":400,"height":320}
{"type":"degraded","component":"mqtt|rosbridge|video","detail":"..."}
{"type":"pong","ts":1794136000000}
```

- `task` 的 `data` 是 `mission_bridge` 原始回执（字段与 MQTT 回执一一对应），App 直接沿用现有 `CommandAck/Feedback/Result` 解析。
- App 断线重连后先 `GET /api/v1/tasks?limit=5` 做状态对齐，再恢复 WS 订阅（WS 不做消息回放）。

## 7. MQTT topic 与 ACL

### 7.1 账号

| 账号 | 用途 | 权限 |
|---|---|---|
| `gateway` | 网关 | **write** `amr/cmd/#`；**read** `amr/cmd/ack|feedback|result`、`amr/status/#`、`amr/alert`、`amr/trace` |
| `robot` | ROS `mqtt_client` 桥 | **read** `amr/cmd/#`；**write** `amr/cmd/ack|feedback|result`、`amr/status/#`、`amr/alert`、`amr/trace` |

`allow_anonymous false`：未认证客户端连 CONNECT 都过不了，"匿名可写控制通道"从根上消失。
两个 listener（1884 TCP / 9002 WS）共用同一套 `password_file` + `acl_file`（Web 端现在也走 HTTP/WS，9002 仅保留给调试）。

### 7.2 acl_file

```
# 默认段：任何已认证客户端只读回报（当前无匿名客户端）
topic read amr/cmd/ack
topic read amr/cmd/feedback
topic read amr/cmd/result
topic read amr/status/#
topic read amr/alert
topic read amr/trace

user gateway
topic write amr/cmd/#
topic read amr/cmd/ack
topic read amr/cmd/feedback
topic read amr/cmd/result
topic read amr/status/#
topic read amr/alert
topic read amr/trace

user robot
topic read amr/cmd/#
topic write amr/cmd/ack
topic write amr/cmd/feedback
topic write amr/cmd/result
topic write amr/status/#
topic write amr/alert
topic write amr/trace
```

`password_file` 由 `amr_gateway/scripts/setup_mqtt_auth.sh` 用 `mosquitto_passwd -b` 生成（开发密码写在脚本里并在文档标注：仅限内网仿真，不得用于真机公网）。生成物 `mosquitto.passwd` 加入 `.gitignore`，脚本保证可重建。

### 7.3 与现状的兼容

- `amr/cmd/*` 的 payload 结构完全不变，`mission_bridge` 不改。
- 变化只有三处：谁在发布（网关）、谁在订阅（网关）、broker 是否允许匿名（否）。
- `mqtt_client.yaml` 增加 `broker.username: robot` / `broker.password`。

## 8. 任务状态机（网关侧）

```
                 ┌──────────┐
   POST /tasks → │ CREATED  │
                 └────┬─────┘
                      │ publish ok          publish 失败
                      ▼                        │
                 ┌──────────┐                  ▼
                 │PUBLISHED │──────────────▶ FAILED(MQTT_UNAVAILABLE)
                 └────┬─────┘
        ack ACCEPTED  │  ack REJECTED → FAILED
                      ▼
                 ┌──────────┐  feedback   ┌──────────┐
                 │ ACCEPTED │────────────▶│EXECUTING │
                 └────┬─────┘             └────┬─────┘
                      │ 1.5s 无 ack            │ 4s 无 feedback
                      ▼                        ▼
                 ┌──────────┐  迟到 ack     ┌──────────┐  迟到 feedback
                 │ UNKNOWN  │──────────────▶│  STALE   │──────────────┐
                 └────┬─────┘                └──────────┘              │
                      │ retry(≤2，重打时间戳)                        │
                      └──────────▶ PUBLISHED                          │
                                                                     ▼
                                                              EXECUTING
   ACCEPTED/EXECUTING/STALE + cancel → CANCEL_REQUESTED → 等 result
   result(SUCCEEDED | FAILED | CANCELLED) → 终态
   120s 无 result → TIMEOUT（终态，但迟到 result 可回填 result 字段）
```

语义要点：

- **单任务串行**：已有非终态任务时 `POST /tasks` 返回 `409 TASK_ACTIVE`（与 `mission_bridge` 的 `BUSY` 语义一致，但提前在网关拦截，不浪费一条 MQTT 消息）。
- **重试**：不新建任务，同 `cmd_id` 重新发布，`timestamp_ms` 必须重新生成（修复 §1.3）；最多 2 次，超限终态 `FAILED(RETRY_EXHAUSTED)`。`mission_bridge` 的 `_seen` 幂等保证"已执行过的指令"不会重复执行物理动作，只回放结果。
- **取消**：独立 `cancel cmd_id` 发布 `amr/cmd/cancel`，`target_cmd_id` 指向任务；`NO_ACTIVE_COMMAND` 回执直接终态。
- **TTL**：网关在发布前用 `ttl_ms` 判断自身处理延迟；App 不再需要也不应该自己拼时间戳。
- **审计**：每次 phase 变化写 `audit(ts, actor, action, cmd_id, detail_json)`，actor 来自 token 对应的 `holder`。

### 8.1 SQLite 表

```sql
CREATE TABLE tasks(
  cmd_id TEXT PRIMARY KEY, trace_id TEXT, type TEXT,
  payload_json TEXT, phase TEXT, created_at INTEGER, updated_at INTEGER,
  error_code TEXT, error_msg TEXT, result_json TEXT);
CREATE TABLE audit(
  id INTEGER PRIMARY KEY AUTOINCREMENT, ts INTEGER,
  actor TEXT, action TEXT, cmd_id TEXT, detail_json TEXT);
CREATE TABLE device_lock(
  id INTEGER PRIMARY KEY CHECK (id = 1),
  holder TEXT, expires_at INTEGER, updated_at INTEGER);
```

## 9. 地图版本与缓存

- **版本**：`sha1(f"{w}|{h}|{res}|{origin.x}|{origin.y}|{origin.yaw}|{data}")[:12]`。同一张图稳定，换图必变。
- **落盘**：`~/.amr_gateway/maps/map.pgm` + `map.json`（原子写：先写 `.tmp` 再 `os.replace`）。
- **PGM 编码**：P5，`maxval=255`；`0=占用`、`254=空闲`、`205=未知`（与 `map_server` 导出的 pgm 一致）；**行序上→下**，App 解析后翻转成 OccupancyGrid 的"行 0 在底部"。
- **App 缓存**：Hive box `gateway_map` 存三件套——`version`、`meta`、`pgm` 原始字节（`List<int>`）；启动先读缓存立即出图，再每 15s 取 `/map/meta` 比对版本，不同才下载 PGM 并覆盖缓存。三端共用同一套逻辑。
- **失败语义**：网关没收到地图 → `404 MAP_NOT_READY`，App 继续显示缓存（若有）或"等待地图数据"。

## 10. 控制锁（device_lock）

- 单行表，`holder` 为客户端自报标识（如 `app-<deviceId>`、`web-<sessionId>`）。
- `POST /api/v1/lock`：空闲/已过期/自己持有 → 获取或续租；他人持有 → `409 LOCKED`。
- TTL 默认 60s：App 当前不主动续租，由服务端在每次任务/指令操作时续租（TTL 60s）；`acquireLock()` 已提供但 UI 尚未接入，若要让锁常驻需补定时续租。网关每 1s 清理过期锁并 WS 广播 `lock`。
- **任务/指令校验**：`holder` 必须等于当前锁持有者；若当前无锁，则自动把该 holder 设为持有者（首个操作者获得控制权）。这样 App 与 Web 大屏不会同时抢控，且不要求用户手动"申请权限"。
- 释放：`DELETE /api/v1/lock?holder=`；任务终态不自动释放（避免连续操作频繁抢锁），由客户端退出控制页时释放或等 TTL。
- 审计：获取/续租/释放/被拒都写 `audit`。

## 11. 降级策略

| 故障 | 网关行为 | App 表现 |
|---|---|---|
| MQTT 断 | `/healthz.mqtt=false`；`POST /tasks` 与 `/commands` 返回 `503 MQTT_UNAVAILABLE`；WS 广播 `degraded{mqtt}`；rosbridge 推送不受影响 | 指示灯变红；下发请求返回 `503 MQTT_UNAVAILABLE` 并提示；按钮不禁用；地图、位姿、路径照常 |
| rosbridge 断 | `/healthz.rosbridge=false`；位姿/路径/扫描停更；任务回执仍走 MQTT，任务可下发但看不到机器人运动 | 显示"定位数据中断"；位姿保持最后值并变灰；任务卡仍可看到 ACK/RESULT |
| WS 断 | 客户端连接断开；HTTP 全量接口仍可用 | 指数退避 2→10s 重连，重连后 `resync()` 拉回任务状态；地图走 HTTP 不受影响 |
| 视频断 | 网关不参与 | 相机页按现有逻辑降级到 RTSP / 提示 |
| 网关挂 | 全链路业务中断 | App 顶部连接点变灰；启动脚本 `/healthz` 自检失败会报错并保留日志 |
| 地图未就绪 | `404 MAP_NOT_READY` | 有缓存用缓存，无缓存显示"等待地图数据…" |

## 12. 迁移与兼容

1. **阶段 0（本分支起点）**：现状双直连，`mosquitto.conf` 匿名。
2. **第一阶段（网关上线，App 未切换，仅设计）**：启动脚本拉起网关；网关与旧 App 并存验证 MQTT 回执、地图落盘、WS 推送。此态 broker 需仍允许匿名（否则旧 App 断）。
3. **第二阶段（App 切换，仅设计）**：App 改走 HTTP/WS，删除 App 内 MQTT/rosbridge 客户端；`/map` 改 HTTP 下载；任务改网关；拍照改 `/snapshot`。此时 App 不再依赖 1884/9090。
4. **阶段 3（ACL 收紧，本分支实际落点）**：`allow_anonymous false` + `password_file`/`acl_file`，`mqtt_client` 用 `robot` 账号，网关用 `gateway` 账号。rosbridge 保持监听但只作为调试工具（运维手工连，不进入 App 运行路径）。**本分支直接从阶段 0 落地到阶段 3**：仓库中没有第一阶段/第二阶段的过渡提交，`mosquitto.conf` 已关闭匿名。
5. **回滚**（没有过渡提交可回退，不能只回退一处）：
   - App 回滚：`git revert` 本分支的 App 提交；必须与 ACL 一起回退——旧 App 没有 MQTT 账号，只回退网关或只回滚 App 都会断。
   - 网关回滚：`amr_start.sh --no-gateway` 只跳过网关拉起，脚本仍成功退出；当前 App 没有旧版直连客户端，跳过网关后 App 业务不可用。
   - ACL 回滚：`git checkout <本分支起点> -- amr_sim_ws/src/amr_comm/config/mosquitto.conf`（同时删除 `mosquitto.passwd` / `mosquitto.acl`），重启 mosquitto。
   - 数据库无破坏性迁移：SQLite 文件独立，删掉即可重建。

## 13. 明确不做的部分及理由

| 不做 | 理由 |
|---|---|
| TLS / mTLS | 单设备、内网仿真、无公网暴露；证书签发与轮换成本远高于收益。token 只用于"防误连"，不是安全边界。真机接入公网时在网关前加反向代理（https/wss）+ 证书，网关代码无需改协议。 |
| Protobuf / gRPC | 载荷小（位姿 20Hz、扫描 4Hz、任务事件低频），JSON 可读、curl/浏览器可直接调试；gRPC 在 Web 端还要 grpc-web 代理，反而多一层。 |
| InfluxDB | 没有长期时序分析/报表需求；任务与审计用 SQLite 存储即可。仿真机资源紧张，不额外跑时序库。 |
| MinIO | 地图小于 1MB、快照单文件，直接落盘 + HTTP 下载足够；对象存储的价值在"多副本/大规模"，当前不存在。 |
| Redis | 单进程网关，任务与锁都在进程内 + SQLite；不需要跨进程缓存，也不想多一个常驻服务。 |
| EMQX | mosquitto 已满足单 broker + ACL + 账号密码；EMQX 功能强但资源占用高，与"仿真机同时跑 Gazebo/Nav2"冲突。 |
| Go 网关 | 与 `mission_bridge` 同语言可直接复用 JSON 契约与调试习惯；单进程 QPS 远低于 Python 上限；不引入第二套工具链。 |
| 网关转发视频 | 媒体流走 MediaMTX 的 WebRTC/HLS 更合适，网关转码/转发会成为瓶颈。 |

## 14. 已知风险

1. **单点**：网关进程挂掉则业务全断。缓解：启动脚本拉起 + `/healthz` 自检 + 失败保留日志；后续可用 systemd 重启策略。
2. **启动顺序**：网关对 `/map` 使用自己的 DDS 订阅 + `transient_local`（keep_last depth 1），可晚于 Nav2 加入仍拿到 latched 地图（实测 Nav2 起来约 2 分钟后启动网关仍收到 `/map`），网关不必抢在 Nav2 之前启动。rosbridge 的 QoS 首注册锁定只影响经由 rosbridge 的客户端（含调试工具），不影响网关自己的 DDS reader。
3. **令牌明文**：token 在 `gateway.json` 与 App 常量中；内网仿真可接受，公网部署必须换 TLS + 动态令牌。
4. **WS 带宽**：扫描按 4Hz、每 4 个点取 1 个点推送；若后续要全量点云需评估。
5. **时钟混用**：ROS 侧 `use_sim_time`，任务 `ttl_ms` 用墙钟判断（网关与 `mission_bridge` 都在墙钟侧），文档与代码注释需明确，避免未来把 `stamp` 混进 TTL。
6. **PGM 翻转**：行序约定（上→下）+ App 翻转是易错点，已写进 §9 与代码注释；验证以"地图与 Gazebo 世界方向一致"为准。
7. **SQLite 并发**：HTTP 线程与 asyncio 线程都写库，统一通过一个 `threading.Lock` + 短事务；WAL 模式降低锁竞争。
8. **Android/iOS 明文 HTTP**：App 走 `http://` 需要平台允许 cleartext（Android `usesCleartextTraffic`、iOS ATS 例外），与现有 `ws://`/`http://` 视频链路一致；若上 HTTPS 需同步调整。
